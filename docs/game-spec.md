# NPC妨害ゲーム 実装仕様

## 合意した遊び方

- 開始・再挑戦の前に、所持能力からその回に使う1種類を選ぶ。所持能力は次回以降も使える。
- 現在の所持能力数と同じ回数だけクリアすると、次の能力をランダム解放する。所持能力と解放までの進捗はサーバーに保存する。
- 能力は下表の16種。開閉ゲートを含む。野良プレイでの妨害対策についての議論は終了。ステージに置くドア・スイッチの採否は別件で未定。
- 壁と通行判定はマス単位、経路探索は4方向のA*。NPCの座標・クリック位置・範囲・押し引きは連続座標。斜めにもマスの途中にも移動できる。
- 正式なゲーム状態と勝敗はC++20/Drogonが持ち、TypeScript/Canvasは操作送信と描画を担当する。
- 盤面の描画は1マス約128×128pxを基準にする。NPCと全16種の能力アイコンはドット絵で描く。
- NPCは距離や遮蔽物にかかわらず盤面全体の妨害を設置時に認識し、踏む方が早ければ踏む。マスの途中でも進路を選び直せる。経路が変わった瞬間、その場で0.1秒だけ歩みを止めてから新しい経路を進む。プレイヤーには予定経路を表示しない。
- 最初のステージは16種それぞれ単独でクリア可能にする。以降はギミックと能力の相性を持たせ、ステージ群全体で各能力に活躍の機会を作る。後期の難度は実際のプレイを重ね、最適な能力を使いこなしてぎりぎりクリアできる水準を目指す。

以下は「はい」で一括採用できる実装案。能力名と効果の趣旨は指定どおりとし、初期能力、抽選方法、対象条件、数値、同時刻の優先順、保存形式は初版の設計値とする。

## ステージと1プレイの流れ

現行の11×7マップ、1 NPC、開始セル(1,3)、ゴールセル(9,3)を使う。NPCの中心がスタート中心から出発し、通常速度は毎秒0.8マス。ゴールセルに入った瞬間に敗北、24秒経過まで守ればクリア。期限と到着が同時なら到着を先に扱う。複数NPCを扱う効果は全員に適用できる形にし、初版の登場数は1とする。

1. 方眼紙風のホームに「スタート」「ランキング」「スキン」「意見」を並べる。スタートから「石垣の庭」を選ぶと能力一覧へ進む。初期所持は「経路妨害」。直前の選択を初期選択にする。
2. 「作戦開始」で選択を固定し、NPC・設置物・状態効果・履歴・時計を初期化する。全画面の盤面をクリックして発動する。残り時間・能力・再使用までの時間を盤面の周囲に表示する。
3. 決着時にシミュレーションを止め、結果と今回の解放名を表示する。「再挑戦」は能力選択へ、「中断」はホームへ戻る。
4. クリア時のスコアは、その瞬間の連続座標から、一時障害・状態効果をすべて除いた地形で本物のゴールセルに入るまでの時間。通常速度・最短経路・20ms刻みでサーバーが算出する。Googleログインしたプレイヤーごとの自己ベストを長い順に並べ、同スコアは同順位とする。

## ドット絵と表示倍率

- 初版のCanvas内部解像度は1マス128×128pxとする。11×7の盤面は1408×896pxで、画面幅に応じて縦横比を保って縮小する。
- NPCは初版案として背景透過の32×32px原画を3倍の96×96pxで描く。画像の中心をNPC座標に合わせる。能力アイコンも32×32pxの原画を能力IDごとに1枚用意し、選択画面は64×64px、プレイ中の能力欄は32×32pxで表示する。似た能力は形で区別する（例：ノックバックは太い矢印、範囲パルスは同心円）。
- Canvasのスプライト拡大は `imageSmoothingEnabled = false`、CSSの画像拡縮は `image-rendering: pixelated` を使う。NPCの描画位置だけを内部ピクセルに丸める。サーバーの位置・距離・当たり判定はタイル単位の連続値を保つ。
- クリック座標は盤面の表示矩形を基準に `x = (clientX - left) * 11 / 表示幅`、`y = (clientY - top) * 7 / 表示高` で求める。縮小表示でも同じ場所を狙えることを確認する。例えば盤面中央はどの表示幅でも(5.5, 3.5)を送信する。

## NPCの外見と表情

参考画像に合わせて、三角耳、大きな顔、短い手足、太い輪郭の猫を共通の素体にする。初版案では体・影のマスクと透明な顔パーツを分ける。体色を変えても目・眉・口の線は保つ。黒に近い体色は顔線を明色に切り替え、暗い色でも反応を読めるようにする。

- 「スキン」の上段でしろねこ・茶トラ・ハチワレ・三毛から種類を選び、下段で6種類から平常時の表情を選ぶ。両段のドット絵で組み合わせを確認でき、選択はサーバーに保存する。
- 使用者の平常顔に関係なく、同じ能力を受けた猫には同じ顔パーツを表示する。体色は変えない。表情は演出専用で、移動・命中・勝敗に影響しない。
- 表示優先度は結果 ＞ 能力の反応 ＞ 経路変更 ＞ 開始 ＞ 平常顔。開始は「きりっ」を0.8秒、選んだ経路が実際に変わったときだけ「片眉上げ」を0.6秒。向く先を目線で予告しない。ゴールした猫は「にっこり」、時間切れで阻止された猫は「しょんぼり」を結果画面まで維持する。
- 能力の反応は各NPCへの効果成立時に開始する。瞬間効果は0.8秒、持続効果は少なくとも0.8秒か効果終了までの長い方。空振りでは変えない。壁・ゲートはそのNPCに迂回・待機が発生したときに反応する。期限が過ぎたら現在有効な最優先の顔へ戻す。平常顔は上書き保存しない。
- サーバーは各NPCの表示顔IDを状態に含め、Canvasは受け取った顔を素体に合成する。ポーリングのたびに演出を開始し直さない。外見の保存先は既存プロフィールに `appearance = {idleFace, bodyColor}` を追加する案。開始時に検証して保存し、古いセーブで項目が欠けていれば外見だけ初期値を補う。

距離は1タイル幅を1とする。範囲対象は効果中心からNPC中心までのユークリッド距離が半径以下の全員。CDは成功時から次に使えるまでの実時間。設置物は置いた瞬間から有効になり、期限で消える。盤面のアイコンを囲むリングは設置時に一周し、残り時間に合わせて短くなる。

## 追加候補　目隠し

曲がる直前のNPCに当て、交差点を通り過ぎさせる範囲技。初期案は半径2、持続3秒、CD5秒。採用時は17種目として解放候補・アイコン・初ステージの単独クリア検証に加える。

- 発動時の範囲内のNPCは、その時点の進行方向へ通常速度で直進する。移動開始前なら予定していた最初の一歩の向きを使う。効果中の分岐では、正面が通れる限り直進する。
- 正面が固定壁・閉鎖セル・盤外に続く場合は、その手前のセル中心で左右を判定する。両方通れれば左右を等確率で抽選し、片側だけならそちらへ曲がる。左右とも塞がった袋小路では反転し、四方とも塞がっていれば開通か効果終了まで待つ。抽選した向きは次に塞がるまで保持する。
- 効果中も衝突・罠・ゴール到着は通常どおり処理する。効果終了時はその場の連続座標から通常の最短時間探索へ戻る。

## 発動と衝突

- 点指定は盤面内、セル指定は座標の切り捨て。円形の範囲技は固定壁を越えて対象を選べるが、強制移動では壁を越えない。おとり・偽ゴールの目標には到達可能な足場（固定壁、閉鎖セル以外）を指定する。経路が途切れている間は待機する。
- 壁・ゲート・罠・床・入口は通路セルに置く。スタート、ゴール、NPC中心のあるセルは不可。同じセルに同じ設置物を置くと期限を更新し、ゲートは閉からやり直す。円形フィールドはクリック地点に個別設置。不正な入力はCD消費なし。有効に撃った即時技は命中0体ならCDを50%返し、通常の半分の時間で再使用可能。1体以上命中すれば通常CD。設置技は後から効くため設置成立時は通常CDとする（初版案）。
- ノックバックとパルスは「NPC座標 − クリック座標」を正規化して距離を掛ける。完全一致時は直前の進行方向、開始直後はゴール方向。引き寄せ・渦は中心までの距離を上限とする。NPCの判定は中心点。線分が最初にぶつかる壁・盤外境界の直前で止める。角を同時に横切る場合は両側の隣接セルも検査する。
- 再探索はサーバーの連続座標（1マス＝1.0）を出発点とする。セル中心にいるときは通常の4方向A*を使う。中心間を歩行中なら現在位置を一時ノードとし、前後のセル中心へそれぞれ通行可能な線分で接続する。
- 強制移動で中心間の線を外れた場合は、着地点から現在セルの中心と上下左右の隣接セル中心までを候補にする。実移動と同じ壁・角・盤外の衝突判定を線分全体に適用し、直接到達できる候補だけに接続する。現在セルの中心を経由する義務はない。
- 最初の線分も現在位置からの実距離で所要時間を積算する。減速域の内外で距離を分け、進行方向に沿ってこれから踏む罠や既に付与された効果を計上する。候補までの時間とその先の予想到着時間の合計で選ぶ。表示用に丸めたpx座標は探索に使わない。
- 移動線分が通るセルを順番に処理し、罠・床・入口は侵入時に発動。転送と巻き戻しは着地点だけを検査し、同一時刻の転送連鎖は1回まで。実ゴールへの進入判定は仮目標中も有効。NPC同士の押し合いは行わない。
- 同種の停止・持続減速の再付与は期限を延長し、速度倍率は重ね掛けしない。停止中もステージ時計・CD・設置物の寿命は進む。逆走・巻き戻し用に時刻付き座標を直近8秒保持し、転送は履歴に区切りを入れる。

## NPCの回避判断（初版案）

- 経路の所要時間が変わる設置物は、設置成立後の次の移動前に再探索する。ポータル入口は探索上は通常の床として扱う。入口の設置・消滅だけでは現在の経路を維持し、同タイムの候補も引き直さない。別の理由で再探索しても入口に誘引・回避コストや出口への近道を設定しない。
- カーソルを合わせただけでは回避しない。時間停止・ノックバックなどの即時技はサーバーで発動が成立した瞬間の座標で命中を確定する。偽ゴール・おとりの効果中は変更された目標に対して回避探索する。
- 固定壁は通行不可。一時壁・ゲートは、そのセルへの進入予定時刻に閉鎖中なら、通行可能になるまで手前で待つ時間を到着予測に加える。待って通る経路と今すぐ迂回する経路を比較し、最短のものを選ぶ。罠・床や減速フィールド・渦の影響も所要時間に反映する。円との交差は区間と円中心の最短距離で判定する。
- 比較の第一基準は現在の目標への予想到着時間。歩行時間に停止・減速・強制移動など既知の効果による所要時間の変化を織り込み、開始時と再探索時に、予想到着時間が最短の経路からランダムに1本を選ぶ。1本だけならその経路を使い、罠の有無が違っても同タイムならどちらも抽選対象とする。選択結果は次の再探索まで保持し、状態取得では引き直さない。壁で通行可能な経路がなくなった場合は待機する。設置・消滅・開閉時には、移動中の区間の前後どちらへ進む場合も現在座標からの残距離で比較する。反転の判断は現在座標で即座に行う。
- 経路変更時の停止はサーバー時間で100ms（20ms刻みで5ステップ）。現在位置から先の予定経路を比較し、別の経路に切り替える場合だけ自力移動を止める。初回の経路決定、予定どおりの曲がり角、同じ経路の再計算では発生しない。経路変更の表情も同じタイミングで開始する。
- 到着時間の比較には切り替え時の停止も含める。停止中に経路を更新しても終了時刻は延長しない。制限時間・能力効果・強制移動は通常どおり進む。
- 予定経路・次の一歩・分岐先は全状態でサーバー内部に保持し、HTTP応答の現行の path とCanvasの経路ハイライトを廃止する。プレイヤーが発動しようとしている能力自体の範囲予告は表示する。

## 時間と状態の更新

C++は単調時計で経過を測り、20ms刻みで通常移動・侵入・状態効果を更新する。受信時までの未処理ステップをすべて進めてからクリックを適用する。HTTPの頻度やタブが隠れていた時間で結果を変えない。時刻が同じ場合の順序は、設置物の周期処理と期限切れ、NPC移動と侵入効果、実ゴール判定、時間切れ判定、プレイヤー入力。残り時間や座標は結果確定時の値を保持する。

地形変更・目標変更・強制移動時に再探索する。次のセルへの通行可否は実移動でも同じ関数を使う。移動方向はA*、位置は浮動小数点で保持し、Canvasはサーバーの座標をタイル幅倍して描画する。描画を補間する場合も当たり判定はサーバーの座標を使う。

## 解放と保存

サーバー側のローカル1プロフィールを使う。初期値は owned=["wall"]、clearsSinceUnlock=0。正式なクリアへの遷移時だけ、ゲームと同じロック内で次を実行する。

1. 未所持があれば clearsSinceUnlock に1加算。加算値が現在の所持数に達したら、能力表から所持済みを除き、等確率で1種引く。所持に追加してカウンターを0へ戻す。
2. 新しい所持・カウンター・最後に報酬処理したラウンドIDを一緒に保存する。各開始で一意なラウンドIDを生成。同じIDの再処理は同じ結果を返す。
3. セーブはサーバーの起動ディレクトリを基準に data/progress.json（version=1）。一時ファイルを書き終えて同一ディレクトリ内でrenameした後、結果を公開する。書込失敗時は抽選済みの結果をメモリに保留し再試行する。失敗中は次の開始を受け付けない。読み込みはファイル未作成のときだけ初期化し、破損時はエラーを示す。
4. 敗北・中断は勝数を維持。全解放後は抽選を終了し「全能力解放済み」と表示。1、3、6、…、120勝目で順に解放。サーバー再起動時は所持と進捗を復元して選択画面へ戻る。

## HTTPと画面

| 操作 | 契約 |
|---|---|
| GET /api/state | 現行の盤面・NPC・時間・状態に、roundId、owned、clearsSinceUnlock、nextUnlockAt（全解放ならnull）、能力一覧と説明・CD、selectedAbilityId、設置物と効果の残時間、今回の解放IDを加える。座標単位はタイル幅。 |
| POST /api/start | 本文は abilityId。所持検証後に開始。現行の本文なし開始は初期能力wallを選ぶ。プレイ中の二重開始は409。 |
| POST /api/use | 本文は roundId と盤面上の有限数 x, y。サーバーに記録した選択能力を発動する。旧 /api/block はwall選択中だけセル中心指定として処理。 |
| POST /api/retire | 本文は roundId。未確定の時間を進め、まだプレイ中なら終了してホームへ。既に決着していれば確定済みの結果を返す。 |
| POST /api/skin | 本文は skin（種類）、idleFace（平常時の表情）の一方または両方。指定された項目を検証して保存する。 |
| GET /api/ranking | Googleログインを要求。未ログインは401。同じブラウザの未登録記録を取り込み、順位・表示名・能力・スコアを返す。 |
| POST /api/feedback | 本文は text。本文・ブラウザの匿名ID・投稿日時をSQLiteに保存する。ブロック済みの投稿者には403を返す。 |

各操作は更新後の状態を返す。形式エラーは400、未所持・古いラウンド・CD中・無効な対象は409、保存失敗は503。CanvasはCSS表示サイズから連続座標へ変換して送る。設置能力は対象セル、円形能力は半径をカーソル位置に予告表示する。状態取得は現行の200ms間隔を使い、操作直後は応答で即時更新する。

## 実装順と受け入れ条件

1. 初ステージ「石垣の庭」は11×7で、全能力を試せるよう中央の通路と曲がり角を配置した。操作なしは約21.9秒で敗北。中央の通路を塞ぎ続けると24秒でクリア。斜めの押し出しが壁角を抜けず、着地後に経路へ復帰できること。
   - 128px表示でAからBへ100px進んだ地点では、Bまで28/128マス、Aまで100/128マスとして比較する。前方の減速域が残り28pxのうち10pxだけを覆うなら、減速をその10pxだけに適用する。
   - 斜めの着地点から隣接セル中心へ直行する方が早ければその線分を選び、壁角を横切る候補は除外する。
2. 能力選択、クリア遷移、セーブを接続。未所持の開始を拒否し、結果の繰り返し取得で勝数が増えず、再起動後も所持と途中勝数が一致すること。1勝で2種、次は敗北を挟んでも追加2勝で3種、最後の抽選後は重複も再抽選も発生しないこと。
3. 表の各能力を通常のクリック経由で検証する。半径境界の内外、同時に範囲内の2体、期限前後、CD中の再入力を確認する。時間停止と罠、減速フィールドと粘着床、逆走と巻き戻し、おとりと偽ゴールの対象・持続の違いが表どおりに出ること。
4. ゲートが閉じても中のNPCは出られること、渦が後から入ったNPCにも効くこと、転送直後に履歴を逆走しても壁を横切らないことを確認する。
5. 罠経由3秒・安全路10秒なら罠を踏み、所要時間を逆にすれば迂回すること。設置により戻る方が早くなれば区間途中から反転すること。カーソルだけでは経路が変わらず、画面にもAPIにも予定経路が出ないこと。CD4秒の即時技は空振りなら2秒後、1体以上命中なら4秒後に再使用できること。 経路が3秒・3秒・4秒のテスト盤面では抽選値を変えて3秒の2経路がどちらも選べること、4秒の経路を選ばないことを確認する。
6. 初ステージで能力別に勝てた配置・タイミングを16通り記録できたら、全能力単独クリア条件を満たす。必要に応じて地形・制限時間・能力値を調整する。以降のステージは相性を個別に検証する。高難度の具体的な数値はプレイテストで決める。
7. 同タイムの上下経路から上を選んだ状態で、下に入口を置いても上を進む。上に入口を置けば進入時に転送し、次の移動は出口から再探索した経路に従う。ゲート待ち込み3秒・迂回5秒なら待ち、待ち込み6秒・迂回5秒なら迂回する。
